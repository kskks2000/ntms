# 07-ui — 화면과 디자인

> 최종 수정: 2026-09-06

화면을 만들거나 고치기 전에 읽는다.

## 지금 있는 문서

- [`design-system.md`](design-system.md) — 토큰 · 타이포 · 컴포넌트. **무엇을 쓰는가**
- [`design-guide.md`](design-guide.md) — 새 화면을 만들 때 지켜야 하는 것 · 글쓰기.
  **어떻게 쓰는가**

이 앱의 서명인 **축 어휘**는 [인수인계 문서](../handoff.md) 5절에 있다 —
디자인 규칙이기 전에 "이 앱이 무엇인가" 의 일부이기 때문이다.

## 여기 넣는 것
- 화면 흐름 — 어느 화면에서 어디로 가는가, 되돌아올 수 있는가
- 컴포넌트 규약 — 언제 새로 만들고 언제 기존 것을 쓰는가
- 디자인 토큰과 그 적용 규칙
- 빈 화면·오류·로딩의 문구 기준

## 넣지 않는 것
- 창구 계약(경로·응답 모양) → `06-api/`
- 상태관리·데이터 페칭·빌드 설정, 폴더 컨벤션 → `08-development/`
  (프론트엔드지만 "보이는 것" 이 아니라 **개발 표준**이다)
- 판정·계산 로직 → 화면에 두지 않는다. `packages/shared` 에 두고 서버와 같이 쓴다
- 왜 이 디자인 언어를 골랐는지 → `01-decisions/`

## 작성 팁

**"이 화면이 답하는 질문" 을 먼저 적는다.** 그것이 정해지면 축이 정해지고,
축이 정해지면 무엇을 크게 그리고 무엇을 접을지가 따라온다. 표를 먼저 그리고
축을 나중에 붙이면 축이 안 붙는다.
