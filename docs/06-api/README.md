# 06-api — REST 창구와 외부 연동

> 최종 수정: 2026-09-04

API 를 만들거나 바꾸기 전에 읽는다.

이 저장소는 **NestJS 컨트롤러 기반 REST** 다. GraphQL 은 쓰지 않는다 —
화면이 필요로 하는 모양이 화면마다 다르고, 그 차이를 서버가 창구 단위로
정해 주는 편이 이 도메인에서는 읽기 쉬웠기 때문이다.

## 여기 넣는 것
- 창구 설계 원칙 — 경로 짓기, 상태 코드, 페이지네이션·정렬·필터 규약
- 오류 표현 — `AppError` 코드 체계와 화면이 그것을 어떻게 읽는가
- 쓰기 스키마 규약 — zod 를 컨트롤러에서 `parse` 하는 자리와 기본값 정책
- 외부 시스템 연동 계약 — 엔드포인트, 인증 방식, 재시도·타임아웃
- 하위 호환 정책 (필드를 뺄 때의 절차)

## 넣지 않는 것
- 왜 그렇게 설계했는지 → `01-decisions/`
- 화면에서 어떻게 호출하는지 → `07-ui/`
- 창구 목록 자체 → **코드가 원본이다.** 컨트롤러를 읽는 것이 가장 정확하다

## 주의

**창구 목록을 문서에 복사하지 않는다.** 금방 어긋난다. 여기에는 "왜 이런
모양인가" 와 "새로 만들 때 지킬 규칙" 만 적는다.

정렬 키처럼 **밖에서 들어온 문자열이 그대로 질의에 닿는 자리**는 값을 고정한다.
`actual.controller.ts` 는 조회 스키마에서
`sort: z.enum(['date:desc', 'variance:desc', …])` 로 받는다 — 목록에 없는 값은
컨트롤러를 통과하지 못한다. 열어 두면 Prisma 가 모르는 칸을 받아 500 을 내거나,
더 나쁘게는 의도치 않은 칸으로 정렬한다.

판정과 계산은 창구에 두지 않는다 — `packages/shared` 에 두고 화면과 서버가
같이 부른다. 이유는 `04-architecture/` 와 인수인계 문서에 있다.
