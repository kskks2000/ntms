# 09-testing — 테스트 기준

> 최종 수정: 2026-09-04

테스트를 작성하기 전에 읽는다.

## 여기 넣는 것
- 테스트 종류별 역할과 경계 — 단위/통합/E2E 각각 무엇을 검증하는가
- 무엇을 반드시 테스트하고 무엇은 하지 않는가
- 픽스처·테스트 데이터 생성 방식
- 모킹 정책 — 무엇을 모킹하고 무엇은 실제로 쓰는가
- 커버리지 목표와 그 목표가 의미하는 것

## 넣지 않는 것
- 일반 코딩 표준 → `08-development/`
- CI 파이프라인 구성 → `10-operations/`

## 작성 팁
에이전트는 시키면 테스트를 **많이** 만듭니다. 문제는 의미 없는 테스트예요.
`무엇을 테스트하지 않는가`를 명시하는 게 커버리지 숫자보다 중요합니다.
예: `getter/setter는 테스트하지 않는다`, `외부 API 응답 형태는 계약 테스트로만 검증한다`
