# 배포 따라하기 — 내 PC 에서 띄워 보고, 서버에 올린다

> 최종 수정: 2026-09-13

컨테이너 이미지를 만들어 가동계에 올리는 과정을 **처음 하는 사람이 한 단계씩
따라 할 수 있게** 적었다. 모든 단계에 "이렇게 나오면 정상" 을 붙였다.

- **1부**의 출력은 2026-09-13 에 이 순서 그대로 돌려서 본 것이다.
- **2부**는 이 문서를 쓰며 배포하지는 않았다. 가동계를 바꾸지 않는 선에서
  `deploy.sh` 가 던지는 질의를 서버에 그대로 돌려 정상 출력을 맞췄다.

- 명령 하나하나의 배경 · 서버 최초 준비 · DB 접속 → [`docker/README.md`](../../docker/README.md)
- 가동계 주소 · 시드 적재 · 밟았던 것 → [`배포-절차.md`](배포-절차.md)

## 0. 먼저 그림 한 장

**이미지를 어딘가에 "업로드" 하지 않는다.** 올라가는 것은 소스(git)뿐이고,
이미지는 **서버가 직접** 만든다. 도커 레지스트리도 CI 도 없다.

```
 내 PC                        GitHub                     서버 (www.qqq.ai.kr)
 ─────                        ──────                     ────────────────────
 ① 코드 수정 · 커밋
 ② 로컬에서 컨테이너로 리허설
 ③ git push ───────────────→  dev 브랜치
                                 │
 ④ ssh ntms ─────────────────────┼─────────────────────→ /opt/ntms
                                 └──── git pull ───────→ ⑤ bash docker/deploy.sh
                                                            이미지 빌드 → 교체 → 검증
```

그래서 순서가 둘로 나뉜다. **1부는 내 PC 에서만 일어나고 서버는 전혀 안
건드린다.** 망가뜨려도 괜찮은 곳에서 먼저 한 바퀴 돌려 보는 것이다.

> 로컬 명령은 전부 **Git Bash** 에서, 저장소 루트에서 친다.
> `bash db/migrate.sh` 와 `. ./.env` 가 PowerShell 에서는 안 돈다.
> ```bash
> cd /c/kys/kcastle/claude/ntms
> ```

아래에서 계속 쓸 줄임말이다. **Git Bash 창을 새로 열면 다시 친다.**

```bash
C="docker compose -f docker/docker-compose.yml --env-file .env"
```

## 1부. 내 PC 에서 컨테이너로 띄워 보기

### 1-1. Docker Desktop 켜기

시작 메뉴에서 **Docker Desktop** 을 실행하고, 고래 아이콘이 멈출 때까지(1분 안팎)
기다린다.

```bash
docker info --format '{{.ServerVersion}}'
```

| 결과 | 뜻 |
|---|---|
| `29.7.2` 같은 버전 숫자 | **정상** |
| `failed to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine` | 아직 안 켜졌다. 조금 더 기다린다 |

> 켜자마자 `ntms-*` 컨테이너가 저절로 뜨는 수가 있다. 예전에 띄워 둔 것이
> `restart: unless-stopped` 로 되살아난 것이라 정상이다. 아래 단계가 새것으로 바꾼다.

### 1-2. `.env` 가 도커용으로 충분한지 검사

```bash
$C config -q && echo OK
```

| 결과 | 뜻 · 조치 |
|---|---|
| `OK` | **정상** |
| `required variable POSTGRES_EXPORTER_PASSWORD is missing a value` | 모니터링용 키가 없다. 아래 한 줄을 넣고 다시 검사 |

```bash
printf '\nPOSTGRES_EXPORTER_PASSWORD=issued-by-create-exporter-role-sh\n' >> .env
```

이 값은 자리표시다. 로컬에서는 모니터링을 안 띄우므로 이대로 둔다.
**비어 있으면 postgres 하나만 띄우는 명령까지 거절된다** — compose 는 파일
전체를 한 번에 해석하기 때문이다.

### 1-3. 이미지 만들기

```bash
$C build api web
```

지금 코드로 `ntms-api`, `ntms-web` 두 이미지를 만든다. `docker/Dockerfile.api` ·
`Dockerfile.web` 이 설계도다.

**이렇게 끝나면 정상:**

```
 Image ntms-api:latest Built
 Image ntms-web:latest Built
```

| 걸리는 시간 (이 PC, 16코어) | |
|---|---|
| 처음 | 5분 안팎 |
| 두 번째부터 | 2~3분 |

**중간에 이런 줄이 보여도 정상이다. 멈추지 않는다.**

```
prisma:warn We could not find your Prisma schema in the default locations
```

의존성 설치 중 Prisma 가 빈 껍데기를 만들어 두며 내는 경고다. Dockerfile 이 뒤에서
그 껍데기를 지우고 진짜로 바꾸고, 바뀌었는지 `schema.prisma` 로 검사한다.

확인:

```bash
docker images | grep ntms
```

`CREATED` 가 방금(`About a minute ago`)이면 된다.

### 1-4. DB · Redis 먼저 띄우기

**순서가 중요하다** — DB → 마이그레이션 → 앱. 서버의 `deploy.sh` 와 똑같다.

```bash
$C up -d postgres redis
$C ps
```

`ntms-postgres` 와 `ntms-redis` 의 STATUS 가 **`(healthy)`** 가 될 때까지
`$C ps` 를 몇 번 다시 친다. `(health: starting)` 이면 기다린다.

### 1-5. 스키마 마이그레이션

```bash
bash db/migrate.sh
```

| 결과 | 뜻 |
|---|---|
| `== 마이그레이션 3건 적용 완료` | 밀려 있던 것을 적용했다. **정상** |
| `== 적용할 마이그레이션 없음 (총 3건 기록됨)` | 이미 최신이다. **정상** |

적용 전에 무엇이 대기 중인지만 보려면 `bash db/migrate.sh --status`.

### 1-6. 앱 올리기

```bash
$C up -d api web nginx
$C ps
```

**다섯 개가 전부 `(healthy)` 면 정상.** 1분 안쪽이다.

```
ntms-api        … (healthy)
ntms-nginx      … (healthy)
ntms-postgres   … (healthy)
ntms-redis      … (healthy)
ntms-web        … (healthy)
```

> 로컬에서는 **모니터링 8개를 일부러 안 띄운다.** 서버 전용이다(호스트 전체를
> 들여다보는 node-exporter 같은 것이 있다). 전체를 올리는 `$C up -d` 를 치지 말고
> 위처럼 이름을 적는다.

### 1-7. 살아 있는지 확인

```bash
curl -s http://localhost/nginx-health
curl -s http://localhost/api/health; echo
curl -s -o /dev/null -w "%{http_code}\n" http://localhost/login
```

**정상:**

```
ok
{"status":"ok","db":true,"uptime":9}
200
```

`"db":true` 까지 봐야 한다. `false` 면 api 는 떴는데 DB 에 못 붙은 것이다(3부).

요청이 흐르는 길: `브라우저 → nginx(:80) → web(:3000)` 또는
`→ /api/ → api(:4000) → postgres`. 밖으로 열린 문은 nginx 하나다.

### 1-8. 처음이면 기준 데이터 넣기 (시드)

로컬 컨테이너 DB 가 비어 있으면 로그인할 계정이 없다. **서버에서 쓰는 방식 그대로**
일회성 컨테이너로 넣는다.

```bash
set -a && . ./.env && set +a && \
$C run --rm --no-deps \
  -e ADMIN_DATABASE_URL="postgresql://ntms_admin:${POSTGRES_PASSWORD}@postgres:5432/${POSTGRES_DB:-ntms}?schema=ntms" \
  api node apps/api/dist/scripts/seed.js
```

**정상 (끝부분):**

```
관리자 계정 생성: NTMS / admin
초기 비밀번호: Ntms@2026!log  ← 첫 로그인 후 변경 필요
공통코드 그룹 10건 · 코드 59건 (이미 있는 것은 두었다)
완료.
```

두 번 돌려도 된다 — 있는 것은 두고 없는 것만 넣는다.

왜 이렇게 번거롭게 하나: 시드는 RLS 를 우회하는 `ADMIN_DATABASE_URL` 이 필요한데,
그 값을 **앱 컨테이너에 상시 넣어 두면** 침해 시 테넌트 격리가 통째로 무너진다.
그래서 딱 이 한 번 뜨고 사라지는 컨테이너에만 준다.

### 1-9. 브라우저로 로그인

<http://localhost/login> → `NTMS` / `admin` / `Ntms@2026!log`

비밀번호를 바꾸라는 화면으로 넘어가면 **정상이다.** 시드가 첫 로그인에 변경을
강제한다. 여기까지 되면 이미지 · DB · nginx · RLS 가 한 줄로 이어진 것이다.

> 로그인은 **IP당 5분에 10회**다. 여러 번 틀리면 429 가 난다. 기다리거나
> `$C restart api` 로 카운터를 비운다.

### 1-10. 끄기

| 명령 | 컨테이너 | 로컬 DB 데이터 | 언제 |
|---|---|---|---|
| `$C stop` | 멈춘다 | 남는다 | 보통은 이것 |
| `$C down` | 지운다 | 남는다 | 컨테이너를 새로 만들고 싶을 때 |
| `$C down -v` | 지운다 | **지운다** | 로컬 DB 를 처음부터. 시드부터 다시 한다 |

**1부 끝.** 여기까지 한 번 성공했으면 서버에서도 같은 일이 일어난다.

## 2부. 서버에 올리기

여기부터는 **가동계**다. 한 단계씩 결과를 보고 넘어간다.

### 2-1. 올릴 커밋을 GitHub 에 올린다

서버는 **GitHub 에서** 소스를 받는다. 내 PC 에만 있는 커밋은 절대 안 올라간다.

```bash
git status -sb
git log --oneline origin/dev..dev
```

| 결과 | 뜻 |
|---|---|
| `## dev...origin/dev [ahead 3]` + 커밋 목록 | 올라가지 않은 커밋이 있다. 아래로 올린다 |
| `## dev...origin/dev` (ahead 없음) | 이미 다 올라가 있다 |

```bash
git push origin dev
git status -sb        # [ahead N] 이 사라지면 정상
```

### 2-2. 서버 접속

```bash
ssh ntms
```

`[root@… ~]#` 프롬프트가 나오면 정상. `post-quantum key exchange` 경고는 무시해도 된다.

이후 2-6 까지는 **서버 안에서** 친다.

```bash
cd /opt/ntms
C="docker compose -f docker/docker-compose.yml --env-file .env"
```

### 2-3. 지금 상태를 적어 둔다 — 되돌릴 때 필요하다

```bash
git log --oneline -1
$C ps --format '{{.Name}}\t{{.Status}}'
```

**첫 줄의 커밋 해시 7자리(예: `fd94dba`)를 메모장에 적는다.** 문제가 생기면 여기로
돌아간다(2-8). 컨테이너는 13개(앱 5 + 모니터링 8)가 `Up` 이어야 한다.

### 2-4. 무엇이 올라갈지 미리 본다

```bash
git fetch origin
git log --oneline HEAD..origin/dev
git diff --stat HEAD origin/dev -- db/migration docker .env.example
```

- 첫 명령 목록 = 이번에 올라갈 커밋들
- 둘째에 **`db/migration/`** 파일이 보이면 → DB 스키마가 바뀌는 배포다. 조금 더 긴장한다
- **`.env.example`** 이 보이면 → 새 환경변수가 생겼을 수 있다. 서버 `.env` 에 그 키가
  있는지 본다(값은 화면에 찍지 말고 이름만):

  ```bash
  comm -23 <(git show origin/dev:.env.example | grep -oE '^[A-Z_]+' | sort -u) \
          <(grep -oE '^[A-Z_]+' .env | sort -u)
  ```

  `git show origin/dev:` 를 붙이는 이유: 아직 pull 전이라 서버 폴더의 `.env.example`
  은 **옛것**이다. 그것과 비교하면 이번에 새로 생긴 키를 못 잡는다.

  2026-09-13 기준 **정상 결과는 딱 두 줄**이다. 둘 다 서버에 없어도 된다.

  ```
  JWT_REFRESH_SESSION_EXPIRES_IN     ← 없으면 코드가 12h 를 쓴다
  NAVER_MAP_APPLICATION_NAME         ← 참고용. 코드에서 안 쓴다
  ```

  이 밖의 이름이 나오면 **배포 전에** `.env.example` 의 설명을 읽고 서버 `.env` 에 넣는다.
  compose 가 `:?` 로 요구하는 키가 빠지면 3단계에서 바로 멈춘다.

### 2-5. 배포

```bash
bash docker/deploy.sh
```

화면에 여섯 단계가 차례로 뜬다. 단계마다 볼 것:

| 단계 | 정상일 때 보이는 것 | 무슨 일 |
|---|---|---|
| `== 1/6 사전 점검` | `PUBLIC_ORIGIN = http://www.qqq.ai.kr` · `기존 DB 볼륨 있음 → … (재배포)` | `.env` 필수값이 비었거나 예시값이면 여기서 멈춘다 |
| `== 2/6 소스 갱신` | 마지막 줄에 **로컬에서 push 한 커밋 제목** | `git pull`. `deploy.sh` 자신이 바뀌었으면 새 버전으로 다시 시작한다 |
| `== 3/6 DB · Redis 기동` | `postgres · redis healthy` | 이미 떠 있으니 금방 지나간다 |
| `== 4/6 스키마 마이그레이션` | `적용 완료` 또는 `적용할 마이그레이션 없음` | **앱보다 먼저** 스키마를 바꾼다 |
| `== 5/6 애플리케이션 빌드 및 기동` | 빌드 로그가 길게 흐른 뒤 `nginx 업스트림 재해석 완료` | **가장 오래 걸린다** |
| `== 6/6 헬스체크 및 배포 검증` | 아래 참고 | |

5단계에서 알아 둘 것:

- 서버는 vCPU 2개다. 빌드에 **몇 분에서 10분 안팎** 걸린다. `pnpm-lock.yaml` 이
  바뀐 배포는 의존성 설치부터 다시 하므로 긴 쪽이다. 멈춘 게 아니다.
- 빌드하는 동안 **사이트는 옛 컨테이너로 계속 돈다.** 다만 서버 CPU 를 빌드가
  같이 쓰니 느려진다.
- 빌드가 끝나고 컨테이너를 **바꿔 끼우는 몇 초** 동안은 502 가 날 수 있다.
  무중단 배포가 아니다.

6단계의 **정상 출력**:

```
  전부 healthy
--- API 헬스 (nginx 경유) ---
{"status":"ok","db":true,"uptime":…}
--- 웹 응답 ---
  HTTP 307
--- 스키마 객체 수 ---
78 | 56 | 115
--- RLS 미적용 테이블 (0건이어야 정상) ---
  0건 — 테넌트 격리 정상
--- API 접속 역할 (ntms_app · BYPASSRLS 없어야 정상) ---
ntms_app | f
ntms_exporter | f

배포 완료 — http://www.qqq.ai.kr
```

- 웹이 `307` 인 것은 `/` 가 로그인 화면으로 보내기 때문이라 정상이다.
- `78 | 56 | 115` 는 테이블 · ENUM · RLS 정책 수다. 마이그레이션이 테이블을 더하면 늘어난다.
- `ntms_exporter` 는 모니터링이 붙는 롤이다. 역시 `f` 여야 한다.
- **`RLS 미적용` 이 0건이 아니거나 `ntms_app | t` 면 멈추고 사람을 부른다.**
  화면은 멀쩡한데 테넌트끼리 데이터가 섞이는 상태다.

### 2-6. 서버 안에서 마무리 확인

```bash
git log --oneline -1       # 로컬에서 push 한 마지막 커밋과 같아야 한다
$C ps --format '{{.Name}}\t{{.Status}}' | sort
exit                       # 서버에서 나온다
```

### 2-7. 내 PC 에서 밖의 눈으로 확인

```bash
curl -s http://www.qqq.ai.kr/api/health; echo
```

그리고 브라우저로 <http://www.qqq.ai.kr/login> 에 들어가 로그인한다.
**새로고침(F5)을 한 번 해서 로그인이 유지되는지까지** 본다 — 서버는 평문 HTTP 라
`.env` 의 `COOKIE_SECURE=false` 가 빠지면 새로고침마다 로그아웃된다(3부).

가동계 관리자 비밀번호는 **저장소에 적지 않는다.** 저장소 밖(비밀번호 관리 도구)에서
받는다.

### 2-8. 문제가 생기면 — 되돌리기

2-3 에서 적어 둔 해시로 돌아간다. 서버에서:

```bash
cd /opt/ntms
git reset --hard <적어 둔 해시>
bash docker/deploy.sh --no-pull
```

- **`--no-pull` 을 빼면 안 된다.** 빼면 2단계가 `git pull` 로 방금 되돌린 것을
  도로 최신으로 당겨 온다.
- 이미지를 옛 소스로 **다시 빌드**하므로 되돌리는 데도 5~10분이 걸린다.
  이미지 버전을 따로 보관하지 않기 때문이다.
- 마이그레이션은 되돌려지지 않는다. 스키마가 바뀐 배포(2-4 에서 `db/migration/`
  이 보였던 경우)를 되돌릴 때는 옛 코드가 새 스키마에서 도는지 먼저 확인한다.

### 2-9. 기록을 남긴다

배포가 끝나면 내 PC 에서 [`배포-절차.md`](배포-절차.md) 맨 위의
**「마지막 배포: 날짜 커밋 해시」** 줄을 방금 올린 것으로 고치고 커밋 · push 한다.
이 줄은 잘 썩는다 — 한 번은 두 번의 배포만큼 뒤처져 있었다. 헷갈리면 언제나
서버에 직접 묻는 것이 정답이다: `ssh ntms 'cd /opt/ntms && git log --oneline -1'`

## 3부. 막히면

| 증상 | 원인 · 조치 |
|---|---|
| `failed to connect to the docker API at npipe:…` | Docker Desktop 이 안 켜졌다 (1-1) |
| `required variable POSTGRES_EXPORTER_PASSWORD is missing a value` | `.env` 에 키가 없다 (1-2). 서버 새로 깔 때는 자리표시로 배포한 뒤 `bash docker/monitoring/create-exporter-role.sh` 로 진짜 값을 발급한다 |
| 빌드 중 `Module not found: Can't resolve '@ntms/shared'` | 빌드 컨텍스트에 `*.tsbuildinfo` 가 들어갔다. `.dockerignore` 에 `**/*.tsbuildinfo` 가 있는지 본다 (2026-09-13 에 넣었다) |
| `ntms-nginx` 가 `restarting` 반복, 로그에 `host not found in upstream` | nginx 가 없는 컨테이너 이름을 기동 시 해석하려 했다. `/mon/` 블록이 `resolver` + 변수 방식인지 본다 (2026-09-13 에 고쳤다) |
| `address already in use` (80) | 로컬: 다른 웹서버·예전 스택이 80 을 쥐고 있다. `netstat -ano \| grep ':80 '` 로 PID 확인 |
| api health 가 `"db":false` | api 는 떴지만 DB 인증 실패. `docker logs ntms-api --tail 30`. 볼륨을 만들 때의 `POSTGRES_PASSWORD` 와 지금 `.env` 가 다르다 — [`docker/README.md`](../../docker/README.md) 2장 |
| 로그인했는데 **새로고침하면 로그아웃** | 평문 HTTP 에 `Secure` 쿠키가 나갔다. 서버 `.env` 에 `COOKIE_SECURE=false`. 로컬 `http://localhost` 는 브라우저가 예외로 받아 줘서 안 난다 |
| 로그인이 `429` | IP당 5분 10회. 기다리거나 `$C restart api` |
| 화면은 뜨는데 데이터가 0건 | 시드를 안 넣었다 (1-8). 로컬 psql 로 볼 때는 `ADMIN_DATABASE_URL` 로 붙는다 |
| 5/6 에서 디스크 부족 | 빌드 캐시가 쌓였다(2026-09-06 기준 12.5GB). 서버에서 `docker builder prune -f` |
| 6/6 `5분 내에 healthy 가 되지 않았다` | 멈춘 컨테이너 로그부터: `$C logs --tail=50 api` (web · nginx 도 같은 방식) |
