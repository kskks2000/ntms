# 10-operations — 배포와 운영

> 최종 수정: 2026-09-06

배포하거나 장애에 대응할 때 읽는다. **압박 상황에서 읽는 문서**이므로
설명보다 **순서가 있는 절차**로 쓴다.

## 여기 넣는 것
- 환경 구성 (dev/staging/prod)과 환경별 차이
- 배포 절차와 롤백 절차 — 번호 매긴 단계로
- CI/CD 파이프라인 구성 — 빌드·검사 단계, 실패 시 대응
- 모니터링 대상 지표와 알림 임계값
- 장애 런북 — 증상별 확인 순서
- 정기 작업 (백업, 배치, 인증서 갱신)

## 지금 있는 문서

- [`배포-절차.md`](배포-절차.md) — 가동계 주소 · 배포 · 시드 적재 · 밟았던 것
- [`모니터링.md`](모니터링.md) — Prometheus · Loki · Grafana, 그리고 왜 그렇게 뒀는지

## 넣지 않는 것
- 시크릿, 토큰, 접속 정보 → **절대 문서에 넣지 않는다.** 저장 위치만 표시한다
- 아키텍처 구조 → `04-architecture/`

## 작성 팁
런북은 "증상 → 확인 → 조치" 3단으로. 장애 대응 중에는 아무도 배경 설명을 읽지 않습니다.

## 아직 없는 것

- `롤백-절차.md` — 지금은 「이전 커밋으로 `git reset --hard` 후 재배포」가
  전부라 따로 쓰지 않았다. 무중단 롤백이 필요해지면 그때 쓴다
- `런북-<증상>.md` — 증상별 확인 순서는 아직 [`모니터링.md`](모니터링.md) 의
  「자주 볼 것」 표가 대신하고 있다
