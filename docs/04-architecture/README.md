# 04-architecture — 시스템 구조

> 최종 수정: 2026-09-04

모듈이 어떻게 나뉘고 무엇에 의존하는지. 구조를 바꾸거나 새 모듈을 만들기 전에 읽는다.

## 여기 넣는 것
- 모듈/패키지 경계와 **의존 방향** (무엇이 무엇을 알아도 되는가)
- 런타임 구성 — 프로세스, 배포 단위, 통신 방식
- 횡단 관심사 처리 방식 (인증, 로깅, 트랜잭션 경계)
- 컴포넌트 다이어그램

## 넣지 않는 것
- **그 구조를 왜 선택했는지 → `01-decisions/`**
  (여기는 "현재 어떻게 되어 있는가", ADR은 "왜 그렇게 했는가")
- 배포 절차 → `10-operations/`

## 작성 팁
의존 방향을 글로 쓰는 것보다 **"금지된 의존"을 명시**하는 게 효과적이다.
예: `domain 레이어는 infra 레이어를 import 하지 않는다` — 에이전트가 이걸 지킨다.
