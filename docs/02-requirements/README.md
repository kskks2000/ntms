# 02-requirements — 무엇을 해야 하는가

> 최종 수정: 2026-09-04

**외부에서 들어온 요구**를 기록한다. 기획, 정책, 법규, 고객 요청처럼
우리가 마음대로 바꿀 수 없는 것들.

## `03-domain/`과의 경계 ← 가장 자주 헷갈리는 지점
> **바깥에서 "바꿔 달라"고 요청할 수 있으면 `02-requirements`,
> 우리가 스스로 정한 동작이면 `03-domain`.**

- "주문 후 7일 내 무료 취소" → 정책이라 바뀔 수 있음 → **02**
- "취소된 주문은 배송 상태로 전이될 수 없음" → 모델 불변식 → **03**

## 여기 넣는 것
- 기능 요구사항, 사용자 스토리
- 업무 정책·규정 (근거 출처와 함께)
- 수용 기준(acceptance criteria)
- 비기능 요구 — 성능 목표, 보안 요건, 규정 준수

## 넣지 않는 것
- 그 요구를 어떻게 구현할지 → `04-architecture/` 또는 `01-decisions/`
- 도메인 개념 정의 → `03-domain/`
