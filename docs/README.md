# 문서 가이드

이 프로젝트의 문서는 모두 `docs/` 아래에 있습니다.
**작업을 시작하기 전에 아래 표에서 읽을 폴더를 고르세요.**

## 라우팅 테이블

| 폴더 | 내용 | 언제 읽는가 |
|---|---|---|
| `00-context/` | 프로젝트 목적, 범위, 용어집 | 처음 참여할 때 / 용어가 낯설 때 |
| `01-decisions/` | ADR — 배경·선택지·결정·트레이드오프 | **거의 모든 작업 전** 관련 항목 확인 |
| `02-requirements/` | 외부 요구, 정책, 수용 기준 | 기능 착수 전 |
| `03-domain/` | 개념 모델, 불변식, 상태 전이 | 업무 로직 구현 전 |
| `04-architecture/` | 모듈 경계, 의존 방향, 런타임 구성 | 구조 변경 / 신규 모듈 |
| `05-data/` | 데이터 모델, 스키마, 마이그레이션 규칙 | 조회·저장·마이그레이션 |
| `06-api/` | REST 창구 설계 원칙, 오류 규약, 외부 연동 계약 | API 개발 |
| `07-ui/` | 화면 흐름, 컴포넌트, 디자인 시스템 | 화면 작업 |
| `08-development/` | 코딩 표준, 네이밍, 에러 처리, 브랜치 전략 | 모든 코드 작업 |
| `09-testing/` | 테스트 종류별 기준, 픽스처, 커버리지 정책 | 테스트 작성 |
| `10-operations/` | 배포 절차, 모니터링, 장애 런북 | 배포 / 장애 대응 |
| `99-reference/` | ⚠️ 레거시 분석, 외부 자료 — **현재 코드 아님** | 기존 시스템 분석 |
| `notes/` *(docs 밖)* | 진행 중 메모 — git 추적 안 함 | 본인 작업 중 |

## 문서 운영 규칙

1. **번호는 ID이지 순서가 아니다.** 한 번 정하면 바꾸지 않는다. 중간에 넣고 싶으면
   빈 번호를 쓴다. 경로가 바뀌면 그 경로를 참조하던 모든 문서가 어긋난다.
2. **문서 하나는 500줄 이내.** 넘으면 쪼갠다. 잘리지 않고 통째로 읽혀야 한다.
3. **폴더 깊이는 2단계까지.** `03-domain/주문-반품기준.md` (O) /
   `03-domain/주문/배송/정책/반품기준.md` (X)
4. **모든 문서 첫 줄에 헤더 한 줄**을 둔다.
   `> 최종 수정: 2026-09-04 · 관련 ADR: 01-decisions/0007-....md`
5. **코드를 바꾼 PR에서 문서도 같이 고친다.** 썩은 문서는 없는 문서보다 나쁘다.
6. **껍데기 폴더는 만들지 않는다.** 빈 폴더는 내용 없는 문서를 부른다.
   다만 폴더의 `README.md`(여기 넣는 것 / 넣지 않는 것 / 예상 파일)는 **내용으로
   친다** — 문서를 어디에 둘지 판단하는 데 실제로 쓰이기 때문이다. 그러니 폴더를
   만들 때 그 README 를 같이 쓰고, **README 조차 쓸 말이 없으면 폴더를 만들지
   않는다.** 이 표에 13개가 적혀 있어도 실제 디렉터리는 그보다 적은 것이 정상이다.

## 어디에 넣을지 헷갈릴 때

> **읽는 순간이 다르면 나누고, 항상 같이 읽히면 합친다.**

각 폴더의 `README.md`에 "여기 넣는 것 / 넣지 않는 것"이 적혀 있다. 그걸 먼저 본다.
