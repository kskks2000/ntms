# 01-decisions — 설계 결정 기록 (ADR)

> 최종 수정: 2026-09-04

**왜 이렇게 되어 있는가**를 결정 하나당 파일 하나로 남긴다.
코드는 "무엇"만 말하고 "왜"는 말해주지 않는다. 이유가 없으면
나중에 누군가(사람이든 에이전트든) 좋은 뜻으로 "고쳐서" 예전 문제를 되살린다.

## 작성 규칙
- 파일명: `NNNN-짧은-제목.md` — 번호는 0001부터 순차, **재사용 금지**
- 템플릿: `0000-template.md` 복사해서 시작
- 한 파일 = 한 결정. 한 화면 넘어가면 그건 설계 문서다
- **결정을 뒤집을 때 기존 파일을 수정하지 않는다.**
  상태를 `대체됨 → NNNN 참조`로 바꾸고 새 ADR을 쓴다.
  히스토리가 남아야 "이미 시도했다 실패한 방법"을 반복하지 않는다
- **트레이드오프 항목을 비우지 않는다.** 여기가 이 문서의 존재 이유다.
  포기한 것 / 감수한 위험 / **재검토 조건**을 반드시 적는다

## 무엇을 ADR로 남기나
"나중에 누가 왜 이랬냐고 물어볼 것 같은 것"만. 보통 프로젝트당 10~30개면 충분하다.
**가장 가치 있는 건 "안 하기로 한 결정"이다** — 없으면 6개월마다 같은 논의를 반복한다.

## 언제 읽나
거의 모든 작업 전. 건드리는 영역의 ADR이 있는지 먼저 확인한다.
